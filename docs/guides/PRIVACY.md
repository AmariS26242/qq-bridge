# 发布前隐私检查

在发布副本中执行 `node scripts/privacy-scan.mjs --tracked-only`；提交前可省略 `--tracked-only`，连同未忽略的新文件一起扫描。`--json` 输出脱敏报告。退出码 0 表示当前规则没有命中，1 表示需要复核，2 表示规则或文件枚举失败。

扫描器检查禁入文件、Windows 用户路径、数字账号形式、疑似凭据字面量、私钥头、带凭据的 URL 和部分高熵字符串。规则存在启发式误报与漏报，扫描通过不能证明不存在任何秘密。

默认规则对测试夹具、示例配置和部分历史文件设有路径豁免；公开账号示例使用 100000001 / 100000002。扫描器对依赖锁中的 SHA-512 校验值及已知常量作精确豁免。修改这些位置时仍需人工复核，不应把新增秘密放进豁免文件。

可复制 scripts/privacy-rules.example.json 为 scripts/privacy-rules.json 添加本机账号与路径的精确规则；该本地规则文件含私人信息，已被忽略。自定义规则即使未写 g 标记也会连续扫描，数字规则不再被熵过滤器跳过。`node scripts/test-privacy-scan.mjs` 验证这些行为。

发布前另行核对实际提交清单，逐文件检查，并在本机将生产配置中的非空敏感值与待发布文本比对，报告只保留命中与文件位置。不得复制 config.json、state、备份、私人音频、对话样本或 Android 签名密钥进入仓库。若秘密已经公开，应先轮换相关凭据；删除当前文件不能撤回已传播的副本。
